FrameMottler.java
- Removed the per-block instance fields blockBlueScaleIndex, blockGreenScaleIndex and blockRedScaleIndex.
- prepareScaleIndicesForBlock now returns an int[] of {blue, green, red} scale lookup indices, or null if the block is undamaged (previously it returned a boolean and stored the indices in fields).
- Renamed setBlockScaleIndices to computeBlockScaleIndices; it now returns the indices instead of setting fields.
- mottleFrame holds the returned indices in a local and passes them to applyMottleBlock, which takes a new int[] scaleIndices parameter.
- Updated the class Javadoc link for applyMottleBlock to the new signature.
- Replaced cachedDamageMaskSegment, damageMaskA, damageMaskB (and the unused damageMasks) with a 3-slot AtomicReferenceArray<DamageMask> cache. DamageMask is a record {index, field} that is never modified after being stored.
- Removed ensureDamageMaskFields; added damageMask(index), which looks in slot index % 3, returns the mask on a hit, and otherwise builds and stores it. (An earlier version skipped storing on interrupted threads; removed because workers are no longer interrupted. Stale frames are now dropped by the model's seek generation, and an eviction by a stale frame only costs an identical rebuild.)
- process() fetches masks segment and segment + 1 into locals and passes them through mottleFrame, prepareScaleIndicesForBlock and sampleDamageMask as new damageMaskA/damageMaskB parameters (previously read from shared fields).
- initialise() clears the damage mask cache, since a new video changes the media seed.

MultiThreadedVideoPlayerModel.java
Architecture: replaced "one pool task per frame that grabs, processes and converts" with a pipeline:
decode thread (sole grabber user) -> processing pool (effects + convert) -> FX thread (ordered display).
The old design let several pool threads call grab() on the one shared FFmpegFrameGrabber, which is not thread safe
(shared demuxer position, decoder state, reused Frame buffers, timestamp/frameNumber fields), and frames could be
assigned to futures out of submission order.

Fields
- Removed frameFutures (ArrayBlockingQueue<Future<PreparedFrame>>).
- Added decodeThread, the single thread allowed to grab during playback.
- Added grabberLock (ReentrantLock). Held from grab() until the frame is stamped, and around setTimestamp() on seek. Nothing blocks while holding it.
- Added seekGeneration (AtomicInteger). Incremented on every seek/close; every frame is stamped with it, and frames with an older value are stale and dropped.
- Added endOfStreamGeneration (volatile int), the generation in which the decoder hit end of stream, or -1.
- Added nextDecodeIndex (guarded by grabberLock) and nextDisplayIndex (FX thread) sequence numbers, reset to 0 on seek.
- Added framesInFlight (Semaphore, framesBuffer permits). Caps frames anywhere in the pipeline; the decode thread takes a permit per frame and it is released exactly once when the frame is displayed or dropped. Bounds memory and makes the decoder block while paused.
- Added decodedFrames (ArrayBlockingQueue<DecodedFrame>), decode thread -> workers.
- Added processedFrames (PriorityBlockingQueue<SequencedFrame>), workers -> FX thread, ordered by generation then index so stale frames surface first.
- pendingAudio changed from ArrayDeque to ConcurrentLinkedQueue (filled by the decode thread, drained by the FX thread).
- playbackOpen and audioOutputEnabled made volatile (read by the decode thread).
- Clock fields (firstTimestampUs, logicalPlaybackBaseUs, playbackStartNs, pauseStartedNs) are now owned by the FX thread only.

Records
- Added DecodedFrame {generation, index, frame (a clone()), frameNumber, timestampUs}.
- Added SequencedFrame {generation, index, prepared}.
- PreparedFrame reduced to {image, frameNumber, mediaTimestampUs, preparedAtNs}; deadline and logical time are now computed at display time.

Decode thread
- startDecodeThread() starts a daemon "video-decoder" thread running runDecodeLoop().
- stopDecodeThread() interrupts it and join()s, so nothing is inside the grabber afterwards. Null-safe.
- runDecodeLoop(): acquire a permit, grab + stamp under the lock (grabAndStampNextVideoFrame), then put() into decodedFrames and submit a worker task outside the lock. Exits only on interrupt or close. Errors go to the FX thread via Platform.runLater.
- readNextVideoFrame() now runs under grabberLock, clone()s the frame (the grabber reuses its buffer), stamps generation and index, records endOfStreamGeneration at end of stream, and no longer processes, converts or touches the clock.
- waitForSeekAfterEndOfStream(): at end of stream the decoder parks until a seek changes the generation or it is stopped.
- Removed canPrepareFrame, decodingTask, prepareNextFrame and decodeNextFrame.

Workers
- Added processNextDecodedFrame(): poll()s a decoded frame, skips it if stale, runs the effects, converts to an Image, and puts a SequencedFrame into processedFrames. Closes the cloned Frame to free native memory. Releases its permit if the frame is dropped. Errors are only reported if the frame is still current.
- processFrame now takes the frame's generation and stops between processors once a seek/close has made the frame stale (replaces the isInterrupted() check).

FX thread
- pumpPlayback drops stale frames at the head, then shows the head only if its index == nextDisplayIndex and it is due. Finishes playback once the decoder hit end of stream and every permit is back (all frames shown), so the last ~2s are no longer cut off.
- Added startPlaybackClock(): the clock starts when the first frame after a start/seek is ready to show, not when it was decoded.
- Deadline = playbackStartNs + (mediaTs - firstTimestampUs) * 1000; logical time = logicalPlaybackBaseUs + (mediaTs - firstTimestampUs).
- While paused, only the first frame after a start/seek is shown; later frames wait for resume.
- displayPreparedFrame takes the frame, its deadline and logical time; headroom log = deadline - preparedAtNs.
- AnimationTimer.handle and displayPreparedFrame no longer declare checked exceptions.

Seek / close / shutdown
- seekTo: under grabberLock (released in finally), setTimestamp() then invalidateQueuedFrames(); then unpark the decode thread, reset the clock and flush audio output. No longer calls prepareNextFrame on the FX thread.
- Added invalidateQueuedFrames() (caller holds grabberLock): increments the generation, resets both indexes, drains both queues (closing cloned frames, returning permits) and clears pendingAudio. Under the lock only stale frames/audio can be in the queues.
- Added discardProcessedFrames() and waitForPipelineToDrain().
- closePlaybackResources: stop the decode thread, invalidate under the lock, wait for workers to leave the FrameProcessors, then close the grabber/converter (previously the grabber could be closed mid-grab, and processors re-initialised while old workers still ran).
- resetPlaybackClock no longer clears pendingAudio or touches threads.
- startPlayback starts the decode thread instead of calling prepareNextFrame.
- shutdown() calls processingPool.shutdownNow() so pool threads don't keep the JVM alive.

Audio
- queueAudio runs on the decode thread under grabberLock; that is why seek can clear stale audio under the same lock without a generation tag.
- Audio is now queued even while muted (queueAudio no longer checks audioOutputEnabled). The decoder runs up to
  framesBuffer (~2s) ahead of the display, so dropping audio at decode time left ~2s of silence after unmuting.
- writeDueAudio, when muted, discards only queued audio that has fallen due (instead of clearing the whole queue),
  so unmuting resumes sound immediately with nothing stale.
- toggleAudioOutput no longer clears pendingAudio; it only flushes the audio line.
- audioOutputEnabled is now only read on the FX thread.
